# Security Policy

## Supported versions

Security reports should concern the current version of CC-PKG whenever possible. Older versions may not receive security fixes.

## Reporting a vulnerability

Do not publicly disclose an unpatched security vulnerability through a GitHub issue, discussion, pull request, or other public channel.

Report security issues privately to the project maintainers using the contact method provided by the repository.

Include, when possible:

- A description of the vulnerability.
- The affected version, command, package, or file.
- Reproduction steps.
- Potential impact.
- A safe proof of concept if necessary.
- A suggested fix.

Never include passwords, API keys, access tokens, or unrelated private information.

## Disclosure

Maintainers may investigate, reproduce, fix, and coordinate disclosure of confirmed vulnerabilities.

Public disclosure should preferably occur after a fix or mitigation is available.

## Safe testing

Only test systems, repositories, servers, or Minecraft environments that you own or have explicit permission to test.

Do not intentionally use CC-PKG to attack, disrupt, compromise, or access systems without authorization.
