# Contributing to CC-PKG

Thank you for helping improve CC-PKG! 🛠️

## Before contributing

Please read:

1. LICENSE
2. CODE_OF_CONDUCT.md
3. SECURITY.md

Check existing issues, pull requests, documentation, and packages before creating new functionality.

## Code and package contributions

Contributions should:

- Have a clear purpose.
- Follow the existing project structure and coding style.
- Avoid unnecessary duplication.
- Preserve compatibility where practical.
- Fail gracefully when required APIs, peripherals, or devices are unavailable.
- Include documentation for new user-facing commands or behavior.

For package-related changes, make sure manifests, repository indexes, source paths, versions, dependencies, and device requirements remain consistent.

## Testing

Before submitting a change, test the affected functionality when practical.

For package-manager changes, test installation, removal, update/upgrade behavior, dependency handling, repository operations, and error handling when relevant.

For package changes, test the normal command path and expected missing-device or missing-peripheral cases.

## Credits

Contributors should be credited appropriately when their work becomes part of the project.

The Lunar Cubes License 1.1 requires published modified versions to retain credits for known contributors who helped create, develop, improve, test, or maintain the software, as well as credit to Cubes Studio for creating the original version.

## Pull requests

Explain:

- What changed.
- Why it changed.
- Which components or packages are affected.
- How the change was tested.

Keep pull requests focused where practical.

## Issues

Include the affected component, version, reproduction steps, exact error output, and relevant Minecraft/CC:Tweaked/device information.

Do not post passwords, API keys, access tokens, or other sensitive information.
